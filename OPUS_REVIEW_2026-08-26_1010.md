# Opus Project Review — 2026-08-26 10:10

Scope: logic correctness + test comprehensiveness. Suite runs clean (59 passed, 0.26s). Architecture is sound: deterministic Python isolates claim/number/calculation grounding; agent handles interpretation. The separation is the right call. Below are real defects and gaps, ranked.

## Logic errors (confirmed by live probe)

**1. `check_outlook_brief_citations` / `validate_review_report` false-reject on hyphenated prose (HIGH).**
`_CLAIM_ID_RE = \bclaim-[a-zA-Z0-9_-]+\b` matches ordinary words. Probe:
`"a claim-based, bottom-up outlook"` → extracts `claim-based` as a claim id → reported as "unknown claim id". Any brief or review finding that writes "claim-based", "claim-level", "claim-by-claim" fails validation with a bogus citation error. Fix: require a digit, e.g. `claim-\d[\w-]*`, or match only the exact id format the agent emits (`claim-\d{3}`).

**2. `extract_numbers` treats years/quarters as ungrounded figures (HIGH).**
Probe: `"fiscal 2027 and Q2 2026"` → `{2.0, 2027.0, 2026.0}`. In `check_claim_text_numbers`, every prose number must trace to the quote/financials. A claim whose text mentions a fiscal year or quarter not literally present in its quote is falsely rejected. This will bite real transcripts constantly. Fix: strip period tokens (`Q1–Q4`, 4-digit years, `FY20xx`) before grounding, or only ground numbers carrying a magnitude/unit cue (`$`, `%`, `bn/m/k`).

**3. Numeric grounding is unit-blind — false accepts (MEDIUM, partly documented).**
`extract_numbers("margin rose 12%")` → `{12.0}`, so a claim asserting `revenue=12` (meaning $12M) is "grounded" by an unrelated 12%. Grounding checks presence, not meaning/scale/unit. The reviewer stage is the intended backstop — make that dependency explicit in code comments, since `check_numeric` reads as stronger than it is.

## Lower-severity

- **`check_claim_text_numbers` percent-form widening** (`validate.py:124`): accepting value OR value/100 also lets a fabricated `10` pass when evidence has `0.10`. Minor over-acceptance.
- **`_archive_existing_run`** uses second-resolution timestamps; two prepares in the same second merge into one archive dir. Unlikely, harmless-ish.
- **`sources.py` docstring** still says "Tavily web search/extraction" though the module is now provider-agnostic. Stale.

## Verdict

Core design trustworthy; deterministic checks do what they claim *structurally*. But two confirmed false-reject bugs (#1, #2) will fire on normal real-world input, and #3 is a real false-accept. Fix the two regexes first — smallest change, biggest correctness gain — then add the six tests above. Coverage is deep on happy paths, thin on adversarial text-shape edge cases, which is exactly where these bugs live.
